# B24. Design and implement access control of your choice.


For this activity, I chose to design and implement an access control solution for my laptop’s SSD by encrypting it so that only authorised access would be possible. I wanted to do something that clearly matched the idea of access control, not just general security improvement, so I focused on protecting who can and cannot access the data stored on the drive. Since I do not have the Windows Pro version needed for normal BitLocker management, I looked for another practical solution and used VeraCrypt, which is a free and open-source disk encryption tool that supports encrypting a Windows system drive. VeraCrypt’s official documentation explains that it can encrypt the system partition or the entire system drive, which made it a suitable choice for this activity. I chose this because it was a direct way to design an access control system around my own laptop storage: the drive would not simply depend on someone physically having the laptop or SSD, but on whether they also had the correct authentication needed to unlock the encrypted data.

The way I designed the access control was very simple and clear. I decided that access to the SSD should be limited only to me, through a proper unlock method, and that even physical possession of the drive should not be enough for someone else to read its contents. In practice, that meant the SSD itself had to remain unreadable unless it was decrypted correctly. This is what makes the task a true access control design rather than just a backup or cleanup task: I was deciding the rule for access in advance and then implementing it technically. VeraCrypt’s system-encryption documentation explains that when the system drive is encrypted, access depends on the proper authentication before the operating system can be used normally. I found this especially meaningful because it protects against a situation where someone tries to bypass normal account login simply by removing the SSD from the laptop and connecting it somewhere else. Instead of the files being immediately readable, the data remains encrypted and inaccessible without the proper unlock credentials.

After deciding on that design, I implemented the solution by setting up encryption on the SSD and making sure the protection was tied to the correct authentication process. The main purpose of this was to prevent unauthorised access not only through normal everyday use, but also through physical removal of the drive itself. This was one of the most important reasons I chose this activity. A normal Windows sign-in password protects the account at the operating-system level, but if the SSD is removed and connected elsewhere, that alone may not be enough. Encryption adds a much stronger layer because it protects the actual contents of the drive. Microsoft’s BitLocker overview explains this clearly by noting that if someone bypasses normal Windows sign-in by physically removing the drive and attaching it to another device, encryption is what stops them from simply reading the data. Even though I used VeraCrypt instead of standard BitLocker management, the same core security idea applies: the stored data is protected in a way that still matters even if the drive itself is stolen.

Overall, I think this activity matched the instruction very well because I did not just talk about access control in theory — I designed and implemented it in a real and meaningful way on my own laptop. The access control decision was that my SSD should only be accessible through authorised decryption, and the implementation was the encryption of the drive itself. What I found most valuable is that this solution protects against a more serious real-world risk: even if someone somehow stole my SSD, removed it from the laptop, and plugged it into another system, they still would not be able to simply browse my files normally because the data would remain encrypted. That is why I consider this a strong example of access control in practice. It directly controls access to data, protects against unauthorised physical access, and turns the SSD from something that could be read freely into something that requires the correct credentials before any useful information can be obtained.
